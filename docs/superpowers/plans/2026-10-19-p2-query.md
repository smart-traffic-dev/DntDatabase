# DntDatabase P2 — Query Editor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Monaco query editor with multi-statement scripts, streamed Glide results, autocomplete, history, Explain and a backend-enforced Production/read-only guard, on MySQL 5.7/8.x, MariaDB 10.3+ and PostgreSQL 12–17.

**Architecture:** `core` gains the per-statement contract (`Session::execute_one`, `TxState`, `StmtOutcome`, `ExecProgress`, sql_mode-aware `Dialect`, shared lexer, `session_effect`). A new crate `dnt-query` (depends on `core` only) holds every decision: `plan`, `guard`, `run`, `redact`, `explain`. `src-tauri` keeps one query session per tab inside `ConnectionRuntime` and streams `RunEvent`s over a Tauri `Channel`; `store` gets migration 2 (tabs, history). The UI adds Monaco, Glide Data Grid and Zustand stores per tab.

**Tech Stack:** Rust stable (MSVC), Tauri 2, tokio, tauri-specta `=2.0.0-rc.21`, rusqlite. UI: React 19, TypeScript, Zustand, Vitest, `monaco-editor`, `@monaco-editor/react`, `@glideapps/glide-data-grid`. E2E: tauri-driver + WebdriverIO.

**Spec:** `docs/superpowers/specs/2026-10-19-p2-query-design.md` (binding). Shared contracts: `docs/superpowers/specs/2026-10-19-p1-core-design.md`. Carried items: `docs/superpowers/plans/2026-10-19-pre-p2-final-review.md`. Canvas: https://claude.ai/artifact/7Uh7EGUTkNvKgBXUWcBB3B (artboard *Workspace – Query editor*).

**Branch:** `feat/p2-query`, cut from `fix/pre-p2-hardening` after Task 0.

## Global Constraints

- Windows 10/11 x64 first. Code stays platform-neutral. Supported: MySQL 5.7, MySQL 8.x, MariaDB 10.3+, PostgreSQL 12–17.
- Secrets never reach SQLite, logs, `Debug` output or frontend payloads. Exception (spec §7.2): editor content is the user's draft and is stored verbatim in `query_tabs`. History and logs are **always** redacted with `dnt_query::redact`.
- Log level `info` never logs SQL. Level `debug` logs SQL only after `redact`, under target `dnt::sql`.
- `dnt-query` depends on `dnt-core` only (plus serde/serde_json/specta). It has no dependency on Tauri, SQLite or the drivers, except drivers/testkit as dev-dependencies for fixture capture.
- Statement boundaries are computed once, by `core::sql::split`. Byte↔UTF-16 conversion happens only in `dnt-query` (`Utf16Map`). Every offset exchanged with the UI is a UTF-16 code-unit offset into the editor text.
- The backend applies the guard itself, again at `query_run`. The frontend only displays verdicts.
- Values: `batch_size = 500`. Row limit per tab: 1 000 / 10 000 (default) / 100 000 / 1 000 000. `cancel_grace` defaults to 10 s. `query_timeout_s` defaults to 0 (off). Plans are kept for 2 min. History keeps 10 000 rows. Tab autosave debounce is 1 s. `statement_ranges` debounce is 150 ms. At most 50 result tabs per run. Previews are 120 chars. The memory warning shows above 100 000 rows. Reconnect bound is 10 s.
- `Value` serialization follows P1 §3.1. 64-bit integers in exported types carry `#[specta(type = f64)]` (or `Option<f64>`).
- Monaco and its worker are bundled locally through Vite (`loader.config({ monaco })`). No CDN.
- UI copy is English. P2 hides `Format`, `Export…` and `Copy as…`.
- Every Rust task ends with `cargo fmt --all`, then `cargo clippy --workspace --all-targets -- -D warnings`, then `cargo test --workspace`, all green. Every UI task ends with `pnpm --dir ui lint` and `pnpm --dir ui test`, both green.

## Review Focus

1. **mysqldump-style scripts on Production.** A script mixing `/*!40101 SET … */`, `LOCK TABLES`, `/*!40000 ALTER TABLE … DISABLE KEYS */`, many `INSERT`s and `UNLOCK TABLES` must plan quickly. Every statement that is not a whitelisted session `SET` must be Confirm. Tests: `mysqldump_script_on_production` (Task 8) and `plan_10k_statements_fast` (Task 7).
2. **Vietnamese, emoji and CRLF in the editor.** Highlight ranges, error markers, Selection and Cursor targets must land on the exact UTF-16 offsets. A cursor between the two halves of a surrogate pair must never panic. Tests: `utf16_offsets_with_vietnamese_and_emoji`, `cursor_inside_surrogate_pair_snaps` and `crlf_offsets` (Task 7), and `error_offset_pg_position` (Task 10).
3. **Stop pressed just as a statement starts.** The script must stop as `Cancelled`, and no later statement may be sent. Tests: `stop_signal_reaches_execute_one` (Task 10) and `stop_signal_before_send_cancels` (Task 4).
4. **Closing the connection, or the tab, while a run streams.** The run must end with a `done` event, the session must be closed, and nothing may panic. Test: `close_connection_during_run_ends_run` (Task 15).
5. **A restored tab whose connection was deleted.** The tab restores with no connection and Run is disabled. Nothing auto-connects. Test: `restores_tab_whose_connection_was_deleted` (Task 21).

  pub struct MySqlMode { pub ansi_quotes: bool, pub no_backslash_escapes: bool }
  #[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize, specta::Type)]
  #[serde(tag = "engine")]
  pub enum Dialect { #[serde(rename = "mysql")] MySql(MySqlMode), #[serde(rename = "postgres")] Postgres }
  impl Dialect { pub const MYSQL: Dialect; pub fn is_mysql(self) -> bool; pub fn for_kind(kind: DbKind) -> Dialect }
  pub fn is_ident_byte(b: u8) -> bool                  // ASCII alnum, '_', '$', or any byte >= 0x80
  pub enum TokKind<'a> { Word(&'a str), Open, Close, Quoted, ExecComment, Punct(u8) }

  - `no_backslash_escapes`: `'…'` and `"…"` strings have no backslash escape.
  - `split`, `classify` and `strip_comments` all honour both flags. `classify` keeps its two-readings rule, now built on `readings`.

- Produces in `dnt_core::tx`:
  ```rust
  #[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize, specta::Type)]
  #[serde(rename_all = "snake_case")] pub enum TxState { Idle, Active, Aborted }
  impl TxState { pub fn as_str(self) -> &'static str }
  pub enum StmtResult<'a> { Ok, Failed { sqlstate: Option<&'a str>, code: Option<u16> }, Lost }

  The table is spec §4.2. The nuances of PG `tx_state_after` are folded in:
  - A failed `COMMIT`/`ROLLBACK`/`PREPARE TRANSACTION` gives `Idle`, except SQLSTATE class 42, which gives `Aborted` inside a block and `Idle` outside one.
  - `… AND CHAIN` gives `Active`.
  - PG: any other failure while `Active` or `Aborted` gives `Aborted`. `57014` counts as a failure.
  - MySQL: `Ddl` gives `Idle` even when it fails. Code 1213 gives `Idle`. Other failures keep the state.
  - `Lost` always gives `Idle`.
- Produces in `dnt_core::error`:
  - `Timeout { stage, outcome_unknown, was_in_tx }` and `Cancelled { outcome_unknown, was_in_tx }`. The helpers `timeout()`/`cancelled()` set `was_in_tx: false`.

  - New variants, with their `AppError` kind and message:

    | Variant | `kind` | `message` |

    | `PlanExpired` | `plan_expired` | "The run plan expired; run it again." |
    | `Blocked { count: u32 }` | `blocked` | "Statements that change data are blocked on this read-only connection." |

- Produces in `dnt_core::config`: `ConnOptions.query_timeout_s: u32` (serde default 0).
- Drivers in this task pass the real `was_in_tx` at every `Timeout`/`Cancelled` site, and call `sink.result_end(&summary)` with the summary they already build.

  - `query_run`:
    - It takes the plan and re-applies `guard` with the connection config re-read from the repo. Any `Block` → `Blocked { count }`. Any `Confirm` without `confirmed` → `ConfirmationRequired { count }`. A tab already running → `Busy`.
    - It spawns the run and returns its `run_id` at once.
    - `ExecOptions`: `max_rows` = `opts.max_rows` clamped to 1..=1 000 000; `batch_size` 500; `timeout` = `query_timeout_s` if > 0; `cancel_grace` 10 s.

    - `result_id` counts up per run.
    - A `rows` event holds at most `batch_size` rows. A full batch is sent at once. Partial batches are merged and held up to `ROWS_EVENT_INTERVAL`, or until `result_end`.
    - `CancelSent` → `stopping{timeout}`, unless already stopping. `GraceExpired` → `abandoning`.
    - `tx_state` is emitted on change.
    - A statement error → `statement_error`.
    - In explain mode, rows are collected instead of streamed, and `statement_end` emits `explain { plan: parse_plan(..) }`.
  - History: one row per statement passed to `execute_one`.
    - `sql_text` = `redact(text, plan.dialect)`; `kind` = `StmtKindLabel`.
    - `status`: `ok`, `error`, or `cancelled` for kind `cancelled`.
    - `error_kind` = `AppError.kind`; `error_code` = `server_code.or(sqlstate)`. No message is stored.
    - It is written on the blocking pool. A failure logs `warn` and never fails the run.
  - Before each statement: `tracing::debug!(target: "dnt::sql", connection = %id, sql = %redacted, "executing")`.
  - After the run: if any `Ddl` succeeded → `refresh_schema_cache(conn, database or home)`.
  - Finally: `done { stop, elapsed_ms }`.
  - `query_cancel` emits `stopping{user}` once, then `RunCancel::cancel()`. An unknown or finished `run_id` is a no-op `Ok`.
  - `query_close_tab` and `close_connection` cancel any run first. The run still ends with `done`.
  - `query_explain`:
    - It plans `Cursor(cursor)` (one stmt). `Ddl` → `Config { field: Some("explain"), message: "Explain is not available for this statement" }`. `analyze` on a non-`Read` → `Config { …, message: "Explain Analyze is only available for read statements" }`.

    - It runs `guard(…, analyze)` with `plan.explain = true`, then rewrites the stmt's `text`/`kind` to the explain SQL, stores the plan with its `ExplainFormat`, and returns the `PlanView`.

  export interface Suggestion { label: string; kind: 'keyword' | 'function' | 'table' | 'view' | 'column' | 'schema' | 'database'; detail?: string; insertText: string }
  export async function suggest(input: { text: string; offset: number; ranges: [number, number][]; engine: 'mysql' | 'postgres';
    scope: CompletionScope | null; containers: string[]; loadObjects(qualifier: string): Promise<CompletionObject[] | null> }): Promise<Suggestion[]>
  export const useCompletion: { scope(connId: string, db: string): Promise<CompletionScope | null>; invalidate(connId: string, db: string): void }
  export function registerCompletion(monaco: typeof import('monaco-editor'), ctxOf: (model: unknown) => { tabId: string; connId: string | null; db: string | null; engine: 'mysql' | 'postgres' } | null): { dispose(): void }
  export const MYSQL_KEYWORDS: string[]; export const PG_KEYWORDS: string[]; export const MYSQL_FUNCTIONS: string[]; export const PG_FUNCTIONS: string[];
  ```
  Contexts, read from the current statement only (spec §7.3 table):
  - After `FROM`/`JOIN`/`UPDATE`/`INTO`/`TABLE` → tables and views.
  - `x.`, where `x` is an alias or a table of the statement's `FROM`/`JOIN`/`UPDATE` → that table's columns (`detail` = `data_type`).
  - `x.`, where `x` is in `containers` (MySQL databases, PG schemas) → `loadObjects(x)`.
  - After `SELECT`/`WHERE`/`ON`/`BY` → columns of the statement's tables, then keywords.
  - Otherwise → keywords, functions, then tables.

  Aliases follow `name [AS] alias`, with quoted identifiers (backticks on MySQL, double quotes on PG). Inserted identifiers that need it are quoted with the dialect's quote. `queryRun` calls `invalidate` on `done` when a `ddl` statement had a `result_end` and no error.
