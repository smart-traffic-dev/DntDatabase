# P4c DDL Edit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Edit and apply the DDL of views, materialized views, functions, procedures, triggers and events (and create them from per-engine templates) with a byte-exact preview, the backend guard, a stale check against the server's current DDL and explicit outcomes, including MySQL's non-transactional drop gap.

**Architecture:** A pure module `dnt_core::sql::ddl_edit` isolates the one statement of the edited text, parses its `CREATE` header, checks it defines the target object, and builds the engine-specific statement sequence (plus PostgreSQL post-checks, warnings, templates). `src-tauri/src/ddl_edit/` holds open edits and single-use plans, reads catalog facts, and applies on a dedicated session through `crate::ddl_exec`. The UI adds a `ddl` tab kind with a store, an editor tab and a review dialog.

**Tech Stack:** Rust (tokio, serde, specta), Tauri 2 + tauri-specta, React 18 + TypeScript + Zustand + Monaco, Vitest, Playwright (e2e-web).

**Spec:** `docs/superpowers/specs/2026-10-25-p4c-ddl-edit-design.md` (rulings R1–R14 in §10).

**Model per task (for the SDD controller):** each task heading carries `[sonnet]` (mechanical, well-specified) or `[opus]` (design judgement, engine semantics, safety). Reviewers use the same model as the implementer.

## Review Focus

1. A MySQL procedure text followed by a second statement (`… END; DROP TABLE t`, also inside a `DELIMITER $$` block) must be refused before anything is sent → Task 1 test `second_statement_after_body_is_refused`.
2. MySQL trigger edit whose `CREATE` fails after the `DROP` reports `Partial`, `executed == [DROP …]`, `object_state == Missing`, `restore_text` = the original DDL, and the edit becomes a new-object edit → Task 5 test `mysql_failure_after_drop_is_partial_with_restore`, Task 6 test `mysql_trigger_gap_and_restore`.
3. PostgreSQL `CREATE OR REPLACE FUNCTION` with a changed argument list is rolled back by the post-check, leaving exactly the old function → Task 6 test `pg_signature_change_is_rolled_back`.
4. The object changed by another session between open and apply → `PlanStale`, zero statements sent → Task 5 test `stale_object_sends_nothing`, Task 6 test `concurrent_change_is_stale`.
5. Text that defines another object (other name, other schema/database, other kind) is refused → Task 1 test `check_target_refuses_other_objects`.
6. Closing a dirty DDL tab (or the app, or its connection) asks → Task 7 test `closing_dirty_ddl_tab_asks`.

- `pub const MAX_TEXT_BYTES: usize = 1 << 20;`
- `pub fn editable_kind(kind: ObjectKind, server: &ServerInfo) -> Result<(), DbError>` — MySQL family: View, Function, Procedure, Trigger, Event; PostgreSQL: View, MaterializedView, Function, Procedure, Trigger; else `Config { field: Some("kind"), .. }`.

- Errors: `DbError::Config { field: Some("text".into()), message }` with a sentence the user can act on; version gaps `DbError::Unsupported { feature, version }` (e.g. feature `"CREATE OR REPLACE TRIGGER"`, version `"PostgreSQL 14"`).

Rules (all from spec §5.1; implement exactly):
- `isolate`: refuse empty/blank and > `MAX_TEXT_BYTES`; MySQL: refuse any `TokKind::ExecComment` token. MySQL view: `split` must give exactly one statement and `!resplits`. MySQL Function/Procedure/Trigger/Event: if the text contains a `DELIMITER` directive, take `split`'s statements (must be one), else the whole trimmed text; then run the body scanner (below) on it. PostgreSQL: `split` must give one statement, except a text whose tokens contain the words `BEGIN ATOMIC` → whole text minus a trailing `;` (and on PostgreSQL < 14 → `Unsupported { feature: "BEGIN ATOMIC function bodies", version: "PostgreSQL 14" }`). Return the statement trimmed, without trailing `;`.
- Body scanner (MySQL compound kinds): walk `tokenize` tokens tracking paren depth and block depth. At paren depth 0: word `BEGIN` → depth+1, word `CASE` → depth+1, word `END` → if the next token is a word `IF|LOOP|WHILE|REPEAT` consume it, no change; if it is `CASE` consume it and depth−1; else depth−1. A `BEGIN`/`END` is a name (no depth change) when the previous token is `Punct(b'.')`, `Punct(b',')`, `Open`, `Punct(b'=')`, or a word `SELECT|AS`, or the next token is `Punct(b',')`, `Close`, `Punct(b'.')`, `Punct(b'=')`, or a word `FROM|AS`. Depth < 0 → refuse ("unbalanced END"). A `Punct(b';')` at paren depth 0 and block depth 0 ends the statement: the rest must hold only `;` punctuation (comments/blanks are already dropped by `tokenize`), else refuse with "Only one statement can be applied; remove what follows the end of the body." End of text with block depth > 0 → refuse ("BEGIN … END is not closed").
- `parse_header` token walk: `CREATE`; optional `OR REPLACE`; then any of (MySQL) `ALGORITHM = <word>`, `DEFINER = <user>` (use `multi::skip_user`), `SQL SECURITY <word>`; (PostgreSQL) `TEMP|TEMPORARY` → refuse, `RECURSIVE`, `CONSTRAINT`; `AGGREGATE`; kind: `VIEW` | `MATERIALIZED VIEW` | `FUNCTION` | `PROCEDURE` | `TRIGGER` | `EVENT`; `IF NOT EXISTS` → refuse ("IF NOT EXISTS would hide an existing object; remove it."); name = identifier [`.` identifier]. Identifier tokens: `Word` (PostgreSQL: ASCII-lowercased), backtick `Quoted` (MySQL), double-quote `Quoted` (PostgreSQL, or MySQL when `ansi_quotes`), unquoted with doubled quotes collapsed; a single-quoted string is not a name. `create_end` = byte end of the `CREATE` token; `name_span` = start of the first name token to end of the last. Triggers: `on_table` = the identifier (qualified or not) after the first word `ON` at paren depth 0 after the name. MySQL `FUNCTION … SONAME` (word `SONAME` at paren depth 0) → refuse ("Loadable functions cannot be edited here."). `OR REPLACE` followed by `MATERIALIZED` → `Unsupported { feature: "CREATE OR REPLACE MATERIALIZED VIEW", version: "PostgreSQL (none)" }`.
- `check_target`: `h.kind == t.kind` else "The text defines a {h kind}, not a {t kind}."; edit (`t.name = Some(n)`): `h.name == n` else "The text defines `{q}`.`{name}`; renaming through the DDL editor is not supported."; qualifier: MySQL — `None` or `== t.database`; PostgreSQL — required and `== t.schema` ("Qualify the name with its schema: {schema}.{name}"). Trigger: `on_table` name must equal `t.table` (when `t.table` is known); its qualifier, if any, must equal the database/schema; PostgreSQL new trigger: `on_table` qualifier required. New object (`t.name = None`): `validate_identifier(kind, &h.name)`; `h.or_replace` → refuse ("Remove OR REPLACE: the object is new."). MySQL variant (not MariaDB) with `h.or_replace` and kind in {Function, Procedure, Trigger, Event} → `Unsupported { feature: "CREATE OR REPLACE {KIND}", version: "MariaDB" }` with the message pointing to writing `CREATE` (the app drops and re-creates). PostgreSQL trigger with `or_replace` and server version < 14 → `Unsupported { feature: "CREATE OR REPLACE TRIGGER", version: "PostgreSQL 14" }`.

MySQL statements: `DROP PROCEDURE|FUNCTION|TRIGGER|EVENT {q}`; PostgreSQL: `DROP VIEW {q} RESTRICT`, `DROP MATERIALIZED VIEW {q} RESTRICT`, `DROP FUNCTION|PROCEDURE {q}({args}) RESTRICT`, `DROP TRIGGER {quote(name)} ON {qualified table}` (table from `facts.table`, schema from target). Materialized view: append `facts.index_defs` in order.
- Post-checks (PostgreSQL only; `$n` params, one text value):
  - routine: `SELECT count(*)::text || ':' || coalesce(min(p.prokind::text), '') FROM pg_proc p JOIN pg_namespace n ON n.oid = p.pronamespace WHERE n.nspname = $1 AND p.proname = $2`, params `[schema, name]`, expect `"1:f"` / `"1:p"`, failure for Replace: "The argument list changed, so CREATE OR REPLACE would add a second routine instead of replacing it. Use Drop and re-create to change the signature."; for Recreate/new: "After the change there is not exactly one routine named {name}."
  - view / materialized view: `SELECT coalesce((SELECT c.relkind::text FROM pg_class c JOIN pg_namespace n ON n.oid = c.relnamespace WHERE n.nspname = $1 AND c.relname = $2), '')`, expect `"v"` / `"m"`.
  - trigger edit: `SELECT count(*)::text FROM pg_trigger t WHERE t.tgrelid = $1::oid AND t.tgname = $2 AND NOT t.tgisinternal`, params `[table_oid, name]`, expect `"1"`, failure "The trigger was not re-created on {table}.".
  - trigger new: join `pg_class`/`pg_namespace` on `$1` schema, `$2` table (from `on_table`), `$3` name, expect `"1"`.
  - `check_notes`: one human sentence per check ("Before COMMIT: exactly one routine named f exists.").
- Warnings: spec §5.2 list; MySQL gap sentence per kind; trigger order warning when `same_timing_triggers > 0` (uses `timing_event`, `table`); "loses its comment" when `has_comment`, "loses its grants" when `has_grants` (PG Recreate/MV/trigger comment); MySQL routine "Privileges granted on the routine may be revoked when it is dropped."; MV refill; "A RESTRICT drop fails if other objects depend on it; the transaction is then rolled back." on PG drops; always "Each lock wait is limited to 5 seconds.".
- `transactional` = PostgreSQL; `gap` = MySQL variant (not MariaDB) edit of Function/Procedure/Trigger/Event.
- `pub fn strategies(t: &EditTarget, server: &ServerInfo) -> Vec<Strategy>` — new: `[]`; PG View/Function/Procedure: `[Replace, Recreate]`; PG MaterializedView/Trigger: `[Recreate]`; MySQL family View: `[Replace]`; MariaDB others: `[Replace]`; MySQL others: `[Recreate]`.
- `pub fn notes(t: &EditTarget, server: &ServerInfo) -> Vec<String>` — header notes per engine/kind (e.g. MySQL procedure: "MySQL has no CREATE OR REPLACE PROCEDURE: the app checks the text under a temporary name, then drops and re-creates the procedure. Between the DROP and the CREATE it does not exist."; PG Recreate availability; MariaDB: "Applied with CREATE OR REPLACE in one statement.").
- `pub fn template(t: &EditTarget, server: &ServerInfo) -> String` — spec R14; names `new_view`, `new_materialized_view`, `new_function`, `new_procedure`, `new_trigger`, `new_event`; qualified with the target database (MySQL) / schema (PG); trigger table = `t.table` or `table_name`; PG trigger executes `{schema}.trigger_function()`. Exact texts:
  - MySQL view: ``CREATE VIEW `db`.`new_view` AS\nSELECT 1 AS `id` ``
  - MySQL function: ``CREATE FUNCTION `db`.`new_function`(p_value INT)\nRETURNS INT\nDETERMINISTIC\nBEGIN\n  RETURN p_value;\nEND``
  - MySQL procedure: ``CREATE PROCEDURE `db`.`new_procedure`(IN p_id INT)\nBEGIN\n  SELECT p_id;\nEND``
  - MySQL trigger: ``CREATE TRIGGER `db`.`new_trigger` BEFORE INSERT ON `table` FOR EACH ROW\nBEGIN\n  -- Change NEW.<column> here\nEND``
  - MySQL event: ``CREATE EVENT `db`.`new_event`\nON SCHEDULE EVERY 1 DAY\nDISABLE\nDO\nBEGIN\n  -- Work to run on schedule\nEND``
  - PG view: `CREATE VIEW "s"."new_view" AS\nSELECT 1 AS id`; materialized view: `CREATE MATERIALIZED VIEW "s"."new_materialized_view" AS\nSELECT 1 AS id\nWITH DATA`; function: `CREATE FUNCTION "s"."new_function"(p_value integer)\nRETURNS integer\nLANGUAGE sql\nIMMUTABLE\nAS $$\n  SELECT p_value;\n$$`; procedure: `CREATE PROCEDURE "s"."new_procedure"(p_id integer)\nLANGUAGE plpgsql\nAS $$\nBEGIN\n  RAISE NOTICE 'id %', p_id;\nEND;\n$$`; trigger: `CREATE TRIGGER "new_trigger" BEFORE UPDATE ON "s"."table" FOR EACH ROW\nEXECUTE FUNCTION "s"."trigger_function"()`.
