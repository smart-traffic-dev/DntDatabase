## 3. How the work was run (subagent-driven)

**Per task:**
1. An implementer subagent works test-first and makes one commit.
2. A fresh reviewer subagent on opus checks the task's diff.
3. If the verdict is CHANGES_REQUESTED, send the findings back to the same implementer as "Fix round N" (at most 5),
   then have the same reviewer do a scoped re-review of the fix diff only.
4. Minor findings may be batched into the next task.

**Model choice:** haiku for explore/search, sonnet for easy tasks, opus for hard ones and for every reviewer. If
haiku or sonnet answers `model_not_found`, use opus.

**Implementer rules** (give these to every implementer):
- **Workspace.** Work in the `mongo-tools` worktree or branch. Never touch other checkouts. The shell is PowerShell
  5.1 (no `&&`) or Git Bash. If node_modules is missing, run `pnpm --dir ui install` / `pnpm --dir e2e-web install`.
- **Unchanged behaviour.** MySQL, PostgreSQL and Redis behaviour stays the same, existing tests pass, and SQL
  snapshots stay identical.
- **UI copy is English.**
- **Kind branching.**
  - In the UI, no kind literals (`'mysql'|'postgres'|'mongo'|'redis'`) outside `ui/src/engine/`; the ESLint rule
    `KIND_COMPARISON` enforces it. Per-kind decisions are exhaustive switches with `assertNever` in `ui/src/engine/`.
  - In Rust, kind branching uses exhaustive `match` only (the `kind_branches` test).
- **Dependencies.** No new crates or npm packages.
- **Secrets** never leave the machine unredacted.
- **Bindings.** These change only if a Tauri command signature changes. Then run
  `cargo run -p dntdatabase --example export_bindings`, after which `bindings_are_current` passes.
- **Encoding.** Files are UTF-8 without BOM (the `no_bom` test). Never use PowerShell `Set-Content -Encoding utf8`.
- **TDD.** Write failing tests first and show RED, then GREEN.
- **Verification:**
  - `pnpm --dir ui lint`, `pnpm --dir ui test`
  - the relevant e2e spec: `$env:E2E_WEB_PORT='5176'; pnpm --dir e2e-web test <spec>`
  - `cargo fmt --all`
  - `cargo clippy --workspace --all-targets -- -D warnings`
  - the touched crates' tests (DB tests: `$env:DNT_TEST_DB='1'`, `--test-threads=1`)
- **Commits.** One commit per task, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never
  push, amend or skip hooks. Don't dispatch subagents.
- **Report.** Write the full report to a file: what changed, tests, RED/GREEN evidence, files, concerns. Reply with
  only: Status (DONE | DONE_WITH_CONCERNS | BLOCKED | NEEDS_CONTEXT), commit(s), a one-line test summary, concerns,
  and the report path.

## 5. Release process

1. Bump the version in `Cargo.toml` `[workspace.package]`, in `package.json` and in `ui/package.json`.
2. Run `cargo check` (it updates the lockfile).
3. Commit `chore: release X.Y.Z`.
4. Tag `vX.Y.Z`.
5. Run `git push origin main vX.Y.Z`.

`.github/workflows/release.yml` builds the signed installer and `latest.json`. Check it with
`gh release view vX.Y.Z`.
